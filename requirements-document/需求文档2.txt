# 哈基哈米网站重构需求文档

## 一、项目背景

哈基哈米（[hajihami.com](http://hajihami.com/)）是一个以“哈基米”文化为核心的音乐收录与分享平台，目前构建在 Notion 之上。随着用户规模增长、内容量扩大及互动需求提升，现有架构在性能、扩展性、用户体验等方面已无法满足长期发展。为此，需对网站进行完整重构，打造一个**自主可控、功能完善、体验优良、可持续演进**的“哈基米”音乐社区。

---

## 二、项目目标

1. **脱离 Notion 依赖**：构建独立站，拥有完整前后端与数据库。
2. **功能无损迁移**：原有关键功能（搜索、投稿、榜单、分类、互动、社群）全部保留并增强。
3. **体验全面升级**：响应式、加载快、交互流畅、支持夜间模式。
4. **开放生态**：提供开放 API，方便第三方机器人、小程序、App 接入。
5. **可持续运营**：内置数据仪表盘、内容审核后台、激励发放系统，降低运维成本。

---

## 三、用户画像

| 角色 | 描述 | 核心需求 |
| --- | --- | --- |
| 听众 | 浏览、搜索、播放、收藏、评论、分享 | 快、全、准、流畅 |
| 创作者 | 上传音频/封面、填写信息、查看数据、领取激励 | 低门槛、实时反馈、收益透明 |
| 审核员 | 过审/驳回/下架、批量操作、查看日志 | 高效、安全、可追溯 |
| 管理员 | 配置榜单、发放哈气金、发布公告、数据分析 | 一站式后台、可视化、权限分级 |
| 开发者 | 调用开放 API、开发机器人 | 文档清晰、限频合理、版本稳定 |

## 四、功能模块与需求拆解

### 1. 音乐数据库（核心）

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 曲库管理 | 字段：ID、标题、原曲名、UP主、全民制作人、风格标签、时长、BPM、封面图、音频文件、发布时间、播放量、点赞量、收藏量、审核状态、备注 | 字段可扩展；支持批量导入旧数据 |
| 原曲关联 | 一首歌可关联 0-N 个“原曲”条目（标题、作者、外链、类型） | 前端可展示“原曲出处在哪” |
| 多源音频 | 支持本地上传、外链（B 站、网易云、SoundCloud 等）双模式，自动转码 mp3 128k/320k | 转码失败率<1%，支持重试 |
| 封面图 | 自动压缩 WebP，多分辨率 200/600/1200 | CDN 加速，懒加载 |
| 失效检测 | 每日定时任务检测外链失效，标记“需补档”并通知 UP | 检测覆盖率 100%，T+1 完成 |

### 2. 搜索与筛选

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 全文检索 | 支持“歌名/原曲/UP主/风格/歌词”组合搜索，实时联想 | 响应 <300 ms，支持拼音/首字母 |
| 高级筛选 | 风格、有无翻唱、有无 AI、时间区间、播放量区间、排序方式 | 与搜索框联动，URL 可分享 |
| 标签系统 | 多级标签（风格：原教旨/婉约/曼波/电音…；类型：翻唱/原创/AI）；支持用户提报新标签 | 后台可审核标签，滥用可下架 |

### 3. 榜单与推荐

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 哈基周金曲 | 每周一 0 点自动生成：播放量≥阈值且本周新增，排除已上榜 8 周内歌曲；管理员可手动微调 | 支持历史回溯 |
| 本月榜单（无翻唱/AI） | 同上，但过滤翻唱与 AI 标签 | 自动打标准确率>95% |
| 随机推荐 | 首页每分钟刷新 10 首，支持“再来一次” | 缓存 1 min，命中率>90% |
| 个性化推荐 | 基于用户播放/收藏/点赞记录，协同过滤+标签向量混合 | v2 阶段实现，首期可先记录行为 |

### 4. 用户系统

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 注册登录 | 邮箱/QQ 互联/哔哩哔哩 OAuth，头像昵称自动拉取 | 1 秒内完成 |
| 个人主页 | 展示投稿、获赞、播放、收到的哈气金、简介、社交链接 | 支持自定义封面 |
| 收藏/播放历史 | 云端同步，支持公开/私密 | 无限制条数 |
| 等级&徽章 | 播放、投稿、评论、分享等行为得经验，等级徽章展示 | 可配置，防刷 |

### 5. 投稿与激励

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 投稿向导 | 分步：上传音频→填写原曲→选择标签→上传封面→预览→提交 | 支持草稿箱 |
| 重复检测 | 音频指纹（Chromaprint）+ 标题相似度双重检测，疑似重复提示 | 误报率<3% |
| 审核流 | 先机器预审（敏感词、时长、大小），再人工复审；支持打回理由模板 | 初审<5 min，复审 T+1 |
| 哈气金发放 | 管理员后台按“本周金曲”“月度新人”等规则一键发放，链上记录（可选） | 发放记录可导出 |
| 分成结算 | 未来接入广告/打赏，按播放量比例自动结算 | v2 阶段 |

### 6. 互动与社群

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 评论 | 支持一级/二级回复、点赞、举报；敏感词过滤、后审 | 支持@用户 |
| 分享 | 生成卡片（标题+封面+二维码），支持微博/B站/QQ 一键分享 | 图片异步生成<3 s |
| 表情包 | 提供 700+ 表情包 API，评论区可直接插入 | 可用户上传，后台审核 |
| 站外社群 | 保留 QQ 群/腾讯频道，后台可配置群号、频道号，前端展示跳转 | 可统计点击 |

### 7. 管理后台

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| 仪表盘 | 今日新增/播放/投稿/注册/评论/失败任务 | 实时刷新 |
| 内容管理 | 歌曲/评论/标签/用户 的增删改查、批量审核、批量下架 | 支持 Excel 导入导出 |
| 激励管理 | 创建活动、设置规则、上传奖金池、发放记录、申诉处理 | 支持撤回 |
| 系统配置 | 首页公告、随机推荐池、SEO、SMTP、OSS/CDN 密钥、限频策略 | 修改后热更新 |
| 日志审计 | 用户行为、管理员操作、异常错误、登录历史 | 保留 180 天 |

### 8. 开放 API & 机器人

| 子功能 | 需求描述 | 验收标准 |
| --- | --- | --- |
| REST API | /song /search /user /chart /oauth /stats 等，统一 JWT 鉴权，限频 60/min | 文档自动生成 Swagger |
| 公告推送 | 支持 Webhook 到 QQ 机器人、Discord、TG | 失败自动重试 3 次 |
| SDK | Python/Nodejs 示例，方便二创 | 提供 GitHub Repo |

## 五、验收方式

1. 提供测试用例（功能/性能/安全）≥ 200 条，90% 通过视为合格。
2. 进行 72 小时压力测试：1k 并发，接口错误率<1%，内存占用<70%。
3. 交付文档：API 文档、部署手册、运维手册、数据库 ER 图、上线检查清单。
4. 提供 30 天技术保障期：严重 Bug 2 小时内响应，24 小时内修复。
