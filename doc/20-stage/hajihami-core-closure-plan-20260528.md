# 哈基哈米核心闭环与健壮性重规划

更新时间：2026-05-28

本文档替代“继续堆功能”的执行方式。当前阶段目标不是扩展页面数量，而是把音乐社区 MVP 的核心业务闭环跑通、数据准备完整、异常处理可信、验证结果可追溯。

## 1. 当前判断

当前项目不能声明“全部完成”。

已具备的基础：

- 前台主页面已经搭起： 首页、搜索、歌曲详情、榜单、投稿、用户中心、用户主页。
- 后端已有公开音乐接口、投稿审核接口、互动接口、开放 API 和 Webhook 草稿。
- 后台已有音乐 Dashboard、CRUD、哈气金流水、开放平台配置草稿。
- 前台和后端主构建链路可通过，后台 `pnpm build` 可通过。

当前主要风险：

- 后台 `pnpm typecheck` 未通过。
- 三仓仍有未提交改动，不能继续多人覆盖式开发。
- 基础数据和系统参数没有统一初始化清单。
- 核心流程没有端到端验收记录。
- 异常态、空态、权限态、网络失败态没有逐页面确认。
- 路线图里存在“完成记录”和实际验证不一致的内容，需要以实际验收为准。

## 2. 总原则

从现在开始，所有任务按“闭环”验收，不按“页面存在”验收。

一个功能只有同时满足以下条件，才能标记为完成：

1. 前台可操作。
2. 后端接口行为正确。
3. 后台可维护或可审计。
4. 基础数据存在或有初始化脚本。
5. 空态、异常态、权限态有明确表现。
6. 至少通过一条手动或自动验收记录。
7. 文档记录验证命令、验证结果和剩余风险。

## 4. 基础数据与系统参数

目标：前台、后台、后端使用同一套可复现的基础数据。

必须维护的数据：

  - 原教旨
  - 曼波
  - 电音
  - 鬼畜
  - 翻唱
  - 原创
  - AI
- 示例歌曲：
  - 已审核公开歌曲 5-10 首。
  - 待审核歌曲 2 首。
  - 驳回歌曲 1 首。
  - 下架歌曲 1 首。
- 示例用户：
  - 普通听众。
  - 创作者。
  - 审核员。
  - 管理员。
- 榜单数据：
  - 当前周榜。
  - 当前月榜。
  - 历史归档至少 2 期。
- 系统参数：
  - `hajihami.community.links`
  - `hajihami.operation.announcements`
  - `hajihami.operation.recommend_cards`
  - `hajihami.incentive.activity`
  - `hajihami.developer.api_keys`
  - `hajihami.developer.webhooks`
- Webhook 日志表：
  - `music_webhook_log`

交付物：

- 初始化 SQL。
- 系统参数示例 JSON。
- 演示账号说明。
- 基础数据验收清单。

完成标准：

- 新环境执行初始化后，首页、搜索、榜单、投稿审核、开放平台页面都有可展示数据。
- 空数据场景也有单独验证。

## 5. 核心用户闭环

### C2：游客听歌闭环

流程：

```text
打开首页 -> 查看推荐/最新/榜单 -> 搜索 -> 进入歌曲详情 -> 播放 -> 分享
```

必须验证：

- 首页 SSR 有首屏数据。
- 首页无数据时显示空态。
- 搜索支持关键词、标签、风格、排序、时间范围。
- 搜索参数可分享，可前进后退恢复。
- 歌曲不存在时进入歌曲 404 或业务空态。
- 音频地址失效时播放器有错误提示。
- 榜单无数据时不报错。
- 移动端布局不遮挡播放器。

完成标准：

- 游客不登录也能完成浏览、搜索、播放、分享。
- 任何接口失败都不会白屏。

### C3：登录用户互动闭环

流程：

```text
登录 -> 播放 -> 收藏 -> 评论 -> 点赞评论 -> 举报 -> 查看收藏和历史
```

必须验证：

- 未登录点击收藏、评论、举报时触发登录提示。
- 登录失败有明确错误提示。
- token 过期能退出或刷新，不死循环。
- 收藏成功后 `/me/collections` 可见。
- 播放历史同步到 `/me/history`。
- 评论提交失败不丢输入内容。
- 举报重复提交有明确提示。

完成标准：

- 登录用户的关键互动可持久化。
- 私有页面 `noindex`。
- 权限错误不会暴露后台数据。

### C4：创作者投稿审核闭环

流程：

```text
登录创作者 -> 投稿 -> 保存草稿 -> 提交审核 -> 后台审核通过/驳回/下架 -> 前台可见/不可见
```

必须验证：

- 文件格式限制：mp3、flac、m4a。
- 文件大小限制明确。
- 封面上传失败可重试。
- 草稿刷新后仍存在。
- 提交后进入待审核。
- 审核通过后公开接口可搜到。
- 驳回后创作者能看到原因。
- 下架后公开页不可访问。
- 重复点击提交不会重复创建。

完成标准：

- 一首歌从投稿到审核发布全链路可跑通。
- 后台审核日志可追溯。

## 6. 运营后台闭环

### C5：后台基础运营闭环

流程：

```text
管理员登录 -> Dashboard -> 歌曲审核 -> 标签维护 -> 榜单维护 -> 哈气金发放 -> 系统配置
```

必须验证：

- Dashboard 数据可加载，空数据不报错。
- 歌曲列表可筛选、审核、驳回、下架。
- 标签字典可维护。
- 榜单快照可查看。
- 哈气金可批量发放和撤回。
- 系统参数可维护运营配置。
- 权限不足时显示无权限。

当前阻塞：

- 后台 `pnpm typecheck` 未通过。
- 生成 CRUD 页面类型错误还未处理。

完成标准：

- `pnpm build` 通过。
- `pnpm typecheck` 要么通过，要么有明确隔离生成目录的门禁策略。
- 手写新增页面必须零类型错误。

### C6：开放平台闭环

流程：

```text
后台配置 API Key -> 配置 Webhook -> 调用开放 API -> 触发 Webhook -> 查看调用日志
```

必须验证：

- 无 API Key 的公开只读接口可访问。
- 错误 API Key 返回未授权。
- 停用 API Key 返回未授权。
- Webhook 无配置时返回明确状态。
- Webhook URL 失败时有重试和日志。
- Webhook 成功时有日志。
- 后台可查询 Webhook 日志。
- token 不应默认长期明文展示。

完成标准：

- 开发者可以按文档完成一次 API 调用和 Webhook 测试。
- 后台能追踪每次推送结果。

## 7. 异常与健壮性清单

所有核心页面必须覆盖：

- 加载中。
- 空数据。
- 网络错误。
- 401 未登录。
- 403 无权限。
- 404 资源不存在。
- 500 服务异常。
- 重试按钮。
- 移动端布局。
- 深色/浅色主题。

所有核心接口必须覆盖：

- 参数缺失。
- 参数非法。
- 空结果。
- 无权限。
- 重复提交。
- 资源不存在。
- 外部服务失败。
